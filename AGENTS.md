# Работа в T&L

Точка входа команды — [README.md](README.md).
Основные разделы Git: Data/, Analytics/, ML/, utils/, Scraper/. Исследования и рабочие
договорённости ведём в [Buildin](https://buildin.ai/e1d7c3f7-5ae9-4537-993a-f1a84e552025).
Локальный архив Notes/ не включаем в новые коммиты.

- Весь веб-доступ выполняйте через gstack `/browse`; не используйте
  `mcp__claude-in-chrome__*`. Текущий владелец Авито может быть другим агентом:
  не трогайте его вкладки, процессы и очередь.
- Независимые сборы могут работать одновременно в собственных Aside-сессиях,
  очередях и отдельных checkout. Глобальной очереди владельца Авито нет;
  внутри каждого сбора навигация остаётся последовательной.
- Для ограниченного сбора вакансий прочитайте
  [collect-avito](Scraper/skills/collect-avito/SKILL.md). Это общий навык проекта,
  а не подтверждение, что он установлен в каталоге skills каждого участника.
  Маршрут моделей: отдельный Luna low для браузерного пакета, Terra для
  проверки/исключений и PR; ведущий явно делегирует с нужной моделью и коротким
  контекстом. Не выполняйте весь штатный сбор на Sol молча.
  Обычный сбор запускайте готовым `scripts/run.py` (freeze/capture/finalize/publish);
  freeze/capture сами выполняют `preflight.py --probe-aside`, отдельно не дублируйте.
  Не пишите заново временные capture/export-скрипты. Новый случай закрепляйте
  общим исправлением, тестом и обновлением skill; укажите их в том же PR.
  Локальный конфиг `Scraper/collect-avito.local.json` не коммитим; проверка файла
  маршрутизации не заменяет проверку работающего туннеля.
  Отсутствующий/непроверенный конфиг — предупреждение в обычном сборе,
  не доказательство отказа Aside. Строгий аудит сети — `--strict-routing`.
- CSV/JSON храним в Git. Завершённые выгрузки не переписываем. Новый сбор или
  новое преобразование получает новый набор; даты наблюдения, схема полей и
  версия инструкции/кода фиксируются отдельно.
- Общий датасет — `Data/dataset/vacancies.csv`, производный от явно
  зарегистрированных выгрузок в `Data/dataset/sources.json`. Его и manifest
  пересобираем `python3 utils/build_dataset.py`; завершённые исходники неизменны.
  Город/регион означают размещение на сайте. Новый сбор включает обновление
  общего CSV и PR, если публикация не исключена заданием. Контракт —
  [Data/dataset/README.md](Data/dataset/README.md).
- Командный режим публикации (27.10.2026): агент сохраняет проверенный сбор
  в ветке GitHub и доводит его через PR до `main` после проверок, если задание
  не ограничено локальным результатом. Перед публикацией синхронизирует main;
  обязательные reviews и защиту ветки не обходит. Длительный сбор делит на
  завершённые батчи с собственными run_id, не публикуя непроверенные строки.
- Основной результат выгрузки — один самодостаточный CSV: строка на вакансию,
  параметры в отдельных колонках. Анализ читает его через `pd.read_csv`;
  сохраняемый эксперимент закрепляет путь и SHA-256 файла. Архив карточек
  и паспорт остаются дополнительным вариантом проверки происхождения.
  Образец загрузки находится в `ML/00_load_first_export.ipynb`.
- Для исследований сохраняйте существующие пять вопросов шаблона. Перед новым
  чтением проверьте [реестр источников в Buildin](https://buildin.ai/a6ca22ae-62a2-4108-b435-2929a78057c5);
  связывайте исследование с исходной задачей в обе стороны. Не назначайте
  владельцев, дату чтения и статус по предположению.
- В Git не добавляем браузерные профили, cookies, токены, приватные session logs,
  временные sandbox-файлы и локальные настройки доступа.
- Новые DOM-дампы и скриншоты в GitHub не публикуем; при необходимости храним
  локально в diagnostics. Raw JSON, CSV, план и паспорт публикуем.
  Исторические архивы завершённых сборов не переписываем. Короткое описание PR
  формируем `utils/dataset_pr.py`, коммит данных — `data: <run_id> (<N> вакансий)`.
