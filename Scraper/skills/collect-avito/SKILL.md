# Сбор вакансий T&L

Версия 1.7.4, 27.10.2026. Корень проекта содержит `Scraper/extract.js`.
Используйте готовый `scripts/run.py`; его исходники не нужно читать для обычного
запуска. Не создавайте заново capture/export/setup-скрипты в /tmp.

## Актуальная инструкция перед новым сбором

Ведущий **до запуска браузерного агента** выполняет `git fetch origin main`, готовит собственный
checkout/ветку от полученного `origin/main` и заново читает этот SKILL.md из него.
Обновляется весь checkout, чтобы инструкция, runner и extractor соответствовали
одному commit; отдельный файл из GitHub поверх старого кода не копируйте.
Для нового checkout используйте механизм worktree среды; при обычном Git —
`git worktree add -b codex/<уникальная-ветка> <новый-путь> origin/main`.
Незакоммиченные файлы существующего checkout не перезаписывайте.
Ошибка fetch останавливает новый сбор с сообщением человеку; устаревшую копию
молча не используйте. Если origin не указывает на командный репозиторий
`https://github.com/tooscl/salary-navigator` (HTTPS или SSH), используйте его
настроенный upstream: выполните `git fetch upstream main` и создайте checkout
от `upstream/main` вместо `origin/main`. При отсутствии такого remote сообщите
ограничение.

Передайте обоим агентам путь одного подготовленного checkout и его SKILL.md.
Оба агента читают этот файл, а не установленную личную копию или инструкцию
из истории. Между этапами fetch/update не нужен. `freeze` уже сохраняет
`instruction_version`, `instruction_sha256` и `code_git_commit` в plan.json;
в итоговой сводке укажите использованные версию и commit.
Для resume сохраняйте исходный checkout и закреплённые хеши. Обновление
инструкции/кода во время существующего пакета — отдельное исправление по
правилам note-change, а не автоматическая замена перед продолжением.

## Подключённый профиль Aside до браузерных действий

Прочитайте актуальные `/browse`, `aside guide` и `aside guide repl`. Если CLI уже
доступен, сначала выполните `aside host profiles --host local --json`.
Отключённый профиль по умолчанию не означает, что CLI не установлен/не авторизован.
Используйте `profileId` с `connected: true`, без изменения постоянных настроек.
Если он один, выбор автоматический; если их несколько, используйте ранее явно
выбранный профиль либо уточните нужный. Если подключённых нет, попросите открыть
нужный профиль Aside. Не предлагайте переустановку/login без подтверждённой
ошибки установки/авторизации. Ошибка чтения списка — сообщить её, не перебирать
профили вслепую и не менять host/account ради обхода ограничения сайта.

Сохраните выбор для всего пакета в локальном окружении: `TL_ASIDE_PROFILE=<ID>`;
`TL_ASIDE_HOST` по умолчанию `local`, `TL_ASIDE_ACCOUNT` необязателен при первом
вызове: runner определяет его через `aside account status` и закрепляет явно.
Ранее выбранный профиль — ID, явно названный участником/ведущим в этом задании
или сохранённый в TL_ASIDE_PROFILE/локальном закреплении этого пакета. При работе
с другим настроенным host/account читайте список с теми же `--host`/`--account`.
Для ручного REPL фильтров передайте эти значения флагами:
`aside --host <host> --profile <ID> repl` (и `--account <account>`, если выбран).
Переменные TL_ASIDE_* читает наш Python runner, сам Aside CLI их не интерпретирует.
Передавайте одинаковые значения окружения каждому вызову preflight/freeze/capture
и в задание браузерному агенту; не полагайтесь на export из прошлого shell-вызова.
Preflight и runner проверяют список профилей и явно передают выбранный профиль
в REPL; при единственном подключённом профиле TL_ASIDE_PROFILE можно не задавать.
Runner закрепляет host/account/profile в локальном diagnostics/aside-target.local.json
перед первым probe и использует их при capture/resume. При отключении
закреплённого профиля остановитесь; другой профиль вместо него не выбирается.
Фактическую готовность подтверждает REPL probe, не один флаг connected.
ID профиля, списки аккаунтов и локальные настройки в Git не публикуйте.

## Первый запуск и неполное окружение

Если участник скачал проект впервые, просит настройку с нуля или preflight
обнаружил отсутствующие зависимости, прочитайте [FIRST_RUN.md](references/FIRST_RUN.md)
и проведите его до пробного CSV через общий run.py. Не завершайте работу одним
NEEDS_SETUP: помогите подготовить Python, gstack, Aside и авторизацию, создайте
локальные настройки через scripts/setup_workspace.py и повторите проверку.
Входы в аккаунты, разрешения ОС и импорт профиля Happ подтверждает участник;
после его ответа продолжайте с места остановки. Режим сети не угадывайте и не
спрашивайте повторно, если он уже известен. Для Happ генератор создаёт JSON и
ссылку импорта маршрутизации вне проекта, не подписку с сервером. Существующие
настройки не перезаписываются; работающий туннель ради проверки не меняется.
Навык читается по пути из Codex/Claude Code; нестандартный путь /browse задаётся
через --browse-skill или TL_BROWSE_SKILL. Windows и другие агенты требуют
фактического теста, а не обещания совместимости.

## Модели и делегирование

Сначала определите приложение исполнителя и прочитайте [HOSTS.md](references/HOSTS.md):
там точки обнаружения, native-файлы агентов, карта путей и точные параметры.

| Исполнитель | Браузерный пакет | Проверка/исключения и PR |
|---|---|---|
| Codex | Luna `gpt-6-luna`, low | Terra `gpt-6.1-terra`, medium |
| Claude Code | `avito-capture`, `model: haiku` | `avito-review`, `model: sonnet` |

Ведущий явно запускает одного агента на весь пакет, ждёт завершения, затем
передаёт артефакты проверяющему. Это маршрут навыка, не автоматическое изменение
модели текущего чата. Не используйте GPT ID в Claude и не подменяйте оба этапа
моделью ведущего молча. Если native-делегирование/модель недоступны, сообщите
конкретное ограничение и согласуйте замену, продолжая независимую настройку.
Агенты этапов не запускают себя повторно и не создают агента на каждую карточку.
JS/Python извлекают и проверяют структуру без вызова модели на каждую вакансию.

Передайте короткое задание: checkout и его SKILL.md, run_id, точные фильтры,
лимит, этап, конфиг и условия публикации. Проверяющему — пути к артефактам,
не всю историю. Оба этапа используют одну очередь и общий failures.json.
NEEDS_HUMAN сохраняет силу при смене модели; публикация до проверки запрещена.

В --agent-model/--review-model передавайте фактическую модель; для Claude при
недоступном полном ID разрешён alias с явной оговоркой в сводке. Эти поля
не переключают модель. Сохраните имена/ID созданных агентов и сведения о
реальном исполнении. Для разработки навыка новый сбор не требуется: Codex
использует Terra для review и Luna для проверки понятности на сохранённых
материалах; Claude Code — соответственно avito-review и avito-capture.

## Обычный запуск

1. Прочитайте актуальный gstack `/browse`, весь браузерный доступ через Aside.
   Используйте свои сессию, вкладки, run_id и checkout. Независимые чаты могут
   работать одновременно; внутри своей очереди переходы последовательны.
   Не трогайте чужие вкладки, процессы или очередь. До ручного REPL выберите
   подключённый профиль по разделу выше.
2. Уточните только существенные неизвестные условия: география, профессия или
   запрос, фильтры, «первые N» либо «N подходящих», лимит. Не заменяйте режим
   отбора. Команды ниже покрывают первые N одной наблюдённой выдачи; подбор по
   критерию и переход по страницам требуют отдельной проверенной реализации.
3. Сначала используйте [проверенный путь фильтров](references/vacancy-filters.md):
   точная страница пользователя `/vakansii` → checkbox профессии → наблюдённая
   городская ссылка с сохранённым `/vakansii/` и профессией → проверка.
   Не уходите на главную, avito.st или общую ссылку города из футера.
   В собственном checkout от свежего `origin/main` откройте и настройте выдачу
   по `/browse`. Считайте snapshot, подтвердите выбранные контролы и фактический
   URL. Не угадывайте URL и кодировку фильтров. Для неизвестных фильтров держите
   один интерактивный Aside REPL, не переоткрывайте главную ради каждого клика.
4. Запускайте из корня проекта (полные пути к команде допустимы):

   ```sh
   python3 Scraper/skills/collect-avito/scripts/run.py freeze \
     --run-id <новый_id> --url '<наблюдённая выдача>' --limit 30 \
     --geography 'Все регионы' --agent-model <модель_браузерного_агента> --filter-evidence '<что подтверждено в snapshot>'
   python3 Scraper/skills/collect-avito/scripts/run.py capture --run-id <новый_id>
   python3 Scraper/skills/collect-avito/scripts/run.py finalize --run-id <новый_id> --review-model <модель_проверяющего>
   ```

   `freeze` и `capture` сами выполняют preflight --probe-aside. Не повторяйте
   проверку отдельно в том же запуске. Отсутствующий локальный конфиг даёт
   предупреждение; ошибка Aside блокирует работу. Не ищите VPN-конфиги и не
   запрашивайте секреты. Строгий аудит — отдельное явное задание.
   `TL_AVITO_CONFIG` или одинаковый --config у setup/preflight и freeze/capture
   позволяют использовать уже настроенный файл; без отдельного измерения
   live_route_verified=false.

   Очередь замораживается до карточек, сохраняются уникальные ID, порядок и
   отметки продвижения. `capture` читает до 30 карточек в одной Aside-сессии без вызовов модели
   между карточками;
   --batch-size ограничивает пакет. Прерванный freeze восстанавливается с теми же аргументами и --resume.
   Повторный `capture` продолжает по raw и
   checkpoint, не загружает сохранённые ID. Полные тексты карточек не выводятся
   в контекст на успешном пути, только сводка. Искусственных пауз нет.
5. `finalize` проверяет весь пакет, записывает отдельный CSV/JSON, паспорт,
   регистрирует источник и пересобирает общий CSV. Новые параметры автоматически
   становятся колонками. Нормализация сохраняет названия; если обнаружен синоним
   существующего поля, исправьте общую нормализацию с регрессионной проверкой.
   Основной файл команды — `Data/dataset/vacancies.csv`; отдельный самодостаточный
   CSV — `Data/avito_runs/<id>/exports/vacancies_flat.csv`.
   Подробный контракт полей нужен при изменении схемы или обогащении:
   [Data/dataset/README.md](../../../Data/dataset/README.md).
6. Для обычного пакета достаточно проверок `finalize`, `build_dataset --check`
   и сверки краткой сводки. Повторять весь unit suite на каждом неизменённом
   сборе не нужно. При изменении кода выполните относящиеся к нему регрессионные
   тесты. Скрипт не объявляет, что человек прочитал каждую карточку:
   review_method явно фиксирует проверку отрисованного шаблона.
7. Опубликуйте, если задание не ограничено локальным показом:

   ```sh
   python3 Scraper/skills/collect-avito/scripts/run.py publish --run-id <id> \
     --summary '<условия отбора и существенное ограничение>' \
     --title 'Данные: 30 вакансий · без фильтров · Все регионы'
   ```

   Команда проверяет хеши, --check, актуальность main и отсутствие посторонних staged-файлов; добавляет
   только файлы сбора, производные данные и явно зарегистрированные исправления;
   создаёт commit/push/PR с краткой статистикой. --prepare-only только готовит
   stage и текст для просмотра. Прикрепите созданный PR к чату.
   При рассинхронизации main сохраните обе записи реестра и пересоберите
   производные файлы; инструкция нужна только при конфликте:
   [references/edge-cases.md](references/edge-cases.md).
   Проверьте обязательные checks/reviews, head SHA и выполните обычный merge
   с --match-head-commit. Не обходите защиту. Затем проверьте свежий origin/main
   в чистом checkout через build_dataset.py --check. Только после этого
   сообщайте «в main». Полный набор unit-тестов повторно не нужен без новых изменений.

## Ошибка: запись, один повтор, человек

Один run_id и один checkout передаются всем агентам. Счётчик общий для этапов,
URL и исполнителей. Сначала записать любую ошибку: неподдерживаемый API, quoting,
не найденный элемент, не применившийся фильтр, сбой загрузки или проверки.

```sh
python3 Scraper/skills/collect-avito/scripts/run.py record-error --run-id <id> \
  --stage filters --action 'выбор города' --message '<точная ошибка>' \
  --url '<текущая страница>' --agent <фактический_агент>
```

Журнал — `Scraper/runs/<id>/diagnostics/failures.json`, отчёт —
`failure-report.md`. Они локальные, без DOM и секретов. Команды freeze/capture/
finalize/publish сами записывают ошибки. Для ручных действий в фильтрах вызов
record-error обязателен; лог не заменяется сообщением «ещё настраиваю».

После первой ошибки доступен **один** осмысленный повтор с конкретной
коррекцией. Перед ним: `run.py check-stage --run-id <id> --stage filters
--retry-reason '<что исправлено по фактам>'`. После успеха: `run.py stage-ok
--run-id <id> --stage filters --evidence '<что подтвердил snapshot>'`.
У штатных команд причина передаётся как --retry-reason. При новой ошибке
счётчик достигает двух: NEEDS_HUMAN, явное сообщение человеку с ошибкой,
действием/URL и уже выполненной коррекцией. Новые переходы и попытки запрещены.
CAPTCHA/429/ограничение доступа и неверный ID требуют остановки сразу.

Не обнуляйте бюджет передачей проверяющему агенту, новым процессом, вкладкой, URL, checkout
или новым run_id. Новый контрольный прогон после стопа допустим только по
явной дальнейшей инструкции человека. Проверяющий (Terra в Codex или avito-review в Claude Code) может читать локальные логи и
исправлять код офлайн, но не продолжать запросы к сайту вместо человека.

## Что требует участия агента

- CAPTCHA/ограничение IP/429: сохранить checkpoint и остановить переходы.
  Никакого автоматического обхода. Ошибка ID, непрочитанный шаблон или пустое
  описание: REVIEW_REQUIRED, raw неизменяем. Краткое дополнительное ожидание
  до 5 секунд допускается только при наблюдаемом переходном состоянии страницы.
- Новый шаблон: изучить локальную диагностику; исправить **общий** экстрактор или
  runner, добавить воспроизводимый тест, обновить этот skill/ссылку на команду.
  Если extractor изменился, старые raw сохраняются; новое наблюдение получает
  новый run_id. Временный обход не считается завершённым исправлением.
- Расположение: проверьте location_raw и read_status.location. Экстрактор читает
  маркеры адреса или видимый соседний блок «Расположение», исключая карту,
  скрытые подсказки и описание. Пустоту не подменяйте URL или текстом вакансии.
  При разборе первая строка расположения содержит адрес; последующие строки
  могут содержать станции метро и районы и не считаются населёнными пунктами.
- Новый город: `finalize` повторно использует подтверждённые city→region из
  реестра. Неизвестные места требуют проверенного JSON `ID: {city, region,
  evidence}` через --placements. Цитата evidence и city должны встречаться
  в видимом расположении. Не выводите географию из описания или URL slug.
  Если город в видимом расположении отсутствует и участник подтвердил пустое
  значение, передайте `city: ""`, `city_unknown_confirmed: true`, регион и
  точную цитату региона в evidence. Исключение по ID сохраняется в реестре;
  остальные пустые города допускаются только как явно отмеченные пропуски. Исправления runner и skill после capture
  допускаются при регистрации через note-change; исходные и новые хеши сохраняются.
- Новая автоматизация фиксируется **в том же PR**: код, тест и обновление skill.
  До finalize зарегистрируйте каждый нужный файл:

  ```sh
  python3 Scraper/skills/collect-avito/scripts/run.py note-change --run-id <id> \
    --file Scraper/extract.js --reason '<новый случай и исправление>' \
    --validation '<какой тест выполнен и результат>'
  ```

  Повторите для теста и skill. Паспорт сохранит automation_changes, генератор PR
  добавит короткие bullets с файлами, причиной и проверкой. Код без этой записи
  не публикуется вместе с данными. Отдельный PR для исправления без сбора тоже
  должен описывать новый случай, тест и обновлённый маршрут запуска.

## Данные и ограничения

Одна строка на вакансию, все наблюдённые параметры в колонках, полное описание,
пустые значения неизвестны. profession — фильтр отбора, без фильтра пусто.
Город/регион — размещение на сайте. Период зарплаты не выводится из выплат.
Обогащение не запускается без соответствующего задания, по умолчанию not_run.
Правила обогащения и resume с нестандартными карточками — в
[references/edge-cases.md](references/edge-cases.md), читать только при необходимости.
Raw/CSV/JSON, очередь, план и паспорт публикуются; DOM и screenshots остаются
локально в diagnostics. Завершённые наборы не переписываются.

Покажите количество принятых/новых/повторных ID, размер общей таблицы, путь к
CSV и PR. capture_seconds — измеренное чтение и сохранение карточек, отдельно
от setup/review-export/publication. observed_at не заменяет замер длительности.
Не обещайте скорость и расход токенов без сопоставимого измерения.

## Аномалии географии без повторного сбора

`finalize --city-anomaly-policy blank` (по умолчанию) оставляет нераспознанный
город пустым. `--city-anomaly-policy search_filter` заполняет его подтверждённым
единственным городом из плана/фильтра; для «Все регионы» такой режим запрещён.
Всегда сохраняются `location_observed`, `city__source` (card/search_filter/missing),
`city__evidence` и `city_anomaly`. Источник search_filter не выдаётся за текст
карточки; исходные raw и описание не меняются. Метро и районы после строки
адреса не считаются городами. Исторические строки могут не иметь city__source.

Если человек после NEEDS_HUMAN явно разрешил завершить уже сохранённый пакет
без нового сбора, запишите его инструкцию через `run.py resume-offline --run-id
<id> --human-instruction '<точное разрешение>'`. Это разрешает только finalize
и publish, сохраняет старые ошибки и по-прежнему блокирует freeze/capture.
Новая ошибка отзывает разрешение. Без новой инструкции человека команду не
вызывать. Вмешательство фиксируется в локальном журнале; raw не перечитывать
с сайта, существующий план/дату наблюдения не переписывать.
