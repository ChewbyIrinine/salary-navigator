# Первый запуск: от GitHub до CSV

Это инструкция агенту, который впервые получил `collect-avito`. Пройдите путь
до проверенного CSV; отсутствие окружения означает следующий шаг настройки,
а не конец задания. Сохраняйте уже выполненные шаги и продолжайте после действий
участника. Повторный сбор в готовом окружении не требует повторной установки.

## 1. Получить проект и выбрать исполнителя

Скачайте весь [salary-navigator](https://github.com/tooscl/salary-navigator)
(Code → Download ZIP и распаковка либо clone). Откройте папку проекта в агенте
с доступом к локальным файлам и терминалу. Один `SKILL.md` не содержит экстрактор,
контракт CSV и утилиты. Изолируйте рабочую копию, если другой агент пишет в неё.

Если скачан ZIP, это пока архив без Git-истории/remote. Он подходит для чтения
инструкций и подготовки инструментов. Перед новым сбором установите Git по
официальной инструкции gstack и получите отдельную Git-копию, не перезаписывая
папку с распакованным архивом:

```sh
git clone https://github.com/tooscl/salary-navigator.git salary-navigator-git
```

Откройте `salary-navigator-git` как проект. Из него выполняются fetch и создание
рабочего checkout по общему навыку. Не имитируйте историю через `git init` в ZIP
и не подставляйте фиктивный commit. Если локальные настройки уже подготовлены,
передайте их абсолютный путь через `TL_AVITO_CONFIG`/`--config`, как описано ниже.
Секреты и браузерные профили в новую копию не переносите. Если clone/fetch
недоступен, сообщите ограничение до сбора, сохранив результаты подготовки.

Участнику достаточно такого задания:

> Используй Scraper/skills/collect-avito/SKILL.md. Помоги подготовить окружение
> с нуля и собери первые 3 уникальные вакансии общей выдачи всех регионов без
> запроса и фильтра профессии. Сохрани полный текст, все характеристики и
> расположение в CSV. Это локальная проверка, без публикации в GitHub.

Ведущий агент сам организует модели по [HOSTS.md](HOSTS.md): Codex — Luna/Terra,
Claude Code — Haiku/Sonnet; участнику не нужно дописывать имена моделей в этот запрос. Если среда
не умеет такое делегирование, агент сообщает конкретное ограничение и предлагает
согласовать доступный маршрут до начала сбора. Настройку окружения можно
продолжать независимо от этого ограничения.

Codex и Claude Code могут читать этот файл непосредственно из проекта;
личная установка `collect-avito` не обязательна. Для другого агента нужны
чтение файлов, запуск Python и доступ к gstack `/browse`/Aside CLI. Не объявляйте
совместимость с конкретным приложением без реального запуска. Облачный чат
без локального исполнителя этот процесс сам не выполняет.

## 2. Проверить и подготовить инструменты

Проверьте ОС, Python, `aside --help` и наличие gstack `/browse`. На macOS/Linux
интерпретатор обычно `python3`, на Windows — `py -3` или `python`. Во всех
командах ниже заменяйте `python3` на найденную команду, версия нужна 3.10+.

Если Python отсутствует, помогите установить его по
[официальной инструкции Python](https://www.python.org/downloads/), затем
проверьте версию в новом терминале. У скриптов подготовки и экспорта нет
сторонних Python-зависимостей; pandas нужен только для анализа готового CSV.
На macOS участник скачивает установщик для macOS и проходит `.pkg`-мастер;
на Windows — установщик для Windows и его мастер. Если предлагается добавление
Python в PATH, включите его. Затем в новом терминале проверьте `python3 --version`
или `py -3 --version`: ожидается 3.10 или новее. Если Python уже есть,
переустановка не нужна. Ссылку можно открыть вручную без установленного gstack.

Если gstack отсутствует, откройте [официальный репозиторий gstack](https://github.com/garrytan/gstack)
через `/browse` и следуйте его актуальному Install для выбранного агента/ОС.
Если `/browse` ещё нет, дайте ссылку участнику для ручной установки;
не обходите правило проекта другим агентным веб-инструментом.
Официальная инструкция требует Git и Bun (рекомендуемая версия 1.4.2+),
на Windows также Node.js и Git Bash. Для Codex используется `./setup --host codex`
из каталога скачанного gstack, для Claude Code — `./setup`. На Windows
PowerShell-вариант `./setup.ps1` принимает те же аргументы и подсказывает
недостающие зависимости. Проверяйте актуальные требования производителя,
не отключайте системную защиту ради запуска. Не копируйте конфигурацию автора.
Не представляйте наличие `SKILL.md` как доказательство работоспособности браузера.

При установленном Git и отсутствии существующей папки gstack пример для Codex
в macOS/Linux/Git Bash:

```sh
git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/.codex/skills/gstack
cd ~/.codex/skills/gstack
./setup --host codex
./setup --status
```

Для Claude Code используйте каталог `~/.claude/skills/gstack` и `./setup`
вместо флага Codex. В PowerShell зайдите в скачанный каталог и используйте
`./setup.ps1 --host codex` для Codex или `./setup.ps1` для Claude Code. Если setup сообщает
о недостающем Git/Bun/Node, выполните предложенную официальным setup команду
подготовки и повторите его. Если папка уже есть, сначала проверьте её `--status`,
не перезаписывайте её повторным clone. Вернитесь в каталог T&L перед preflight.

Установите [Aside](https://aside.com/download) для ОС участника и откройте
приложение. Страница производителя предлагает macOS и Windows; Linux-процесс
и Windows-проход до CSV в проекте ещё не подтверждены. Следуйте текущей инструкции
Aside для установки CLI: не угадывайте установочные команды. Затем проверьте
`aside --help`. Если команда не найдена, проверьте PATH/установку CLI и откройте
новый терминал. Не подменяйте ошибку установки запуском старого `avito.py`.
На macOS откройте `.dmg`, перенесите Aside в Applications и запустите;
на Windows откройте `.exe` и пройдите мастер установки. Установка приложения
и доступность CLI — две отдельные проверки; страницу загрузки можно открыть
вручную до появления /browse. [Официальная инструкция CLI](https://docs.aside.com/help/developers).
В настройках Aside откройте раздел для разработчиков и установите CLI штатным
средством приложения. Другой документированный вариант — установщик из
официальной инструкции CLI: выберите вкладку своей ОС. Windows-инструкция
проверяет подпись установщика перед запуском; не пропускайте эту проверку.
После установки откройте новый терминал и выполните `aside --help`.

Если CLI уже доступен, сначала проверьте `aside host profiles --host local --json`.
Отключённый default-профиль не требует повторной установки/login: выберите
`connected: true` через `--profile <ID>` для ручного REPL и TL_ASIDE_PROFILE
для preflight/runner (общий раздел SKILL.md). При нескольких подключённых
используйте явно выбранный, при отсутствии попросите открыть профиль Aside.
Постоянный default не меняйте. Только при подтверждённой ошибке авторизации
прочитайте `aside login --help` и помогите участнику
подтвердить CLI в приложении. Пароли и коды участник вводит сам. При нескольких
host/profile проверьте выбор через документированные команды `aside host`.
Вход в аккаунт Авито проверяется в собственной сессии; авторизация автора
проекта не переносится. Cookies, профили и приватные логи не копируются.
Дождитесь сообщения CLI об успешном входе после подтверждения в приложении.
Если CLI не смог сохранить авторизацию, подготовьте доступный приватный путь
по официальной инструкции. При использовании `ASIDE_CLI_AUTH_PATH` передавайте
его всем последующим вызовам Aside; это файл секретов вне репозитория, не
настройка маршрутизации и не содержимое для чата.

Проверяйте успешность каждого шага перед следующим. Если установка требует
системного разрешения или входа, дайте участнику конкретное действие и после
его выполнения повторите проверку; не заявляйте автоматическую установку.

## 3. Создать локальные настройки

Режим берите из задания/подтверждённого окружения. Если он неизвестен, спросите
один раз: без VPN, Happ или другой клиент? Не выбирайте `disabled` только из-за
отсутствующего конфига. При запросе настроить Happ сразу готовьте вариант Happ.

Без VPN:

```sh
python3 Scraper/skills/collect-avito/scripts/setup_workspace.py --mode disabled
```

С Happ сначала проверьте сохранённый конфиг по известному пути и внешний
collector.local.json. Если его нет, попросите участника прислать полный JSON
текущего туннеля; агент сохраняет и готовит копию для импорта по разделу
[«Полный JSON от участника»](../../../VPN_HAPP.md#полный-json-от-участника).
Готовая команда — setup_workspace.py --mode xray --happ-tunnel-json с внешними
--state-dir и --config; формат xray не означает другой клиент.

Отдельный профиль маршрутизации без переноса полного туннеля — альтернативный
вариант, если именно он нужен участнику:

```sh
python3 Scraper/skills/collect-avito/scripts/setup_workspace.py --mode happ
```

Скрипт создаёт `Scraper/collect-avito.local.json`, а для Happ ещё JSON-профиль
и `avito-routing-link.txt` вне checkout. Путь напечатан в результате. Файлы
повторно не перезаписываются: совпадающий запуск безопасен, изменённые настройки
нужно сохранить и выбрать новый `--config`/`--state-dir`. На Windows внешний
каталог по умолчанию находится в LOCALAPPDATA, на macOS/Linux в XDG_DATA_HOME
или `~/.local/share/tl-avito`. Можно выбрать `--state-dir` вне checkout явно.

Для уже имеющегося полного Xray JSON:

```sh
python3 Scraper/skills/collect-avito/scripts/setup_workspace.py --mode xray --xray-config /absolute/private/config.json
```

Это проверка и ссылка на существующий файл, не изменение подписки. Другой
VPN-клиент требует его собственной процедуры; не называйте его Xray/Happ.

Если `/browse` установлен в другом месте, добавьте к выбранной команде
`--browse-skill /absolute/path/to/gstack/browse/SKILL.md`. Скрипт запомнит путь
в локальном конфиге. Для временной проверки поддерживается `TL_BROWSE_SKILL`.
Стандартный внешний collector.local.json обнаруживается автоматически, если
локального конфига проекта нет. Нестандартный общий конфиг передаётся через `TL_AVITO_CONFIG` или
`--config`; один и тот же путь используйте в setup, preflight и командах
`run.py freeze/capture --config`. Иначе runner прочитает конфиг по умолчанию.

## 4. Импортировать Happ

Откройте [VPN_HAPP.md](../../../VPN_HAPP.md), раздел «Создать профиль для импорта».
Покажите участнику готовый `avito-routing-link.txt` и объясните действие:
импортировать в Happ и выбрать профиль у своей подписки. Это не VPN-подписка:
сервер/подписка должны быть у участника. Для предоставленного полного JSON
передайте вместо routing-link готовый avito-tunnel.json из процедуры выше.
Не открывайте автоматически deeplink и не перезапускайте общий туннель.

## 5. Подтвердить готовность и собрать пробу

```sh
python3 Scraper/skills/collect-avito/scripts/preflight.py --probe-aside
```

При `NEEDS_SETUP` устраните указанную зависимость по разделу 2 и повторите.
При `READY_WITH_WARNINGS` можно проверить первую обычную загрузку сайта;
маршрут без независимого измерения остаётся неподтверждённым. Для отдельной
проверки файла маршрутизации добавьте `--strict-routing`: она не доказывает
импорт/активацию профиля или отсутствие CAPTCHA.
У только что созданного неизменённого Happ-профиля ожидается успешная статическая
проверка `tunnel_config`; если Aside тоже готов, итог — `LOCAL_CHECKS_OK` даже
без импорта. Это не подтверждение действующего туннеля. Для первого запуска
Happ выполните строгую проверку один раз после генерации/импорта; затем обычные
freeze/capture проверяют окружение сами. Загрузку сайта проверяйте только после
выбора профиля участником, если настройка Happ входила в его задание.

Точку входа берите из задания или [паспорта маршрутов](vacancy-entry-routes.md).
Не открывайте корневой /vakansii вместо городской страницы.
Дальше выполните основной SKILL.md: собственная сессия, подтверждение фильтров,
замороженная очередь, raw JSON каждой карточки и checkpoint. Малой проверки на
3 карточках достаточно для первого запуска. При CAPTCHA сохраните checkpoint,
не создавайте дополнительные профили и не меняйте IP ради продолжения.

## 6. Получить CSV общим runner

После freeze/capture из основного SKILL.md используйте тот же run_id:

```sh
python3 Scraper/skills/collect-avito/scripts/run.py finalize --run-id <run_id> --review-model <фактическая модель проверки>
```

Проверку выполняет Terra в Codex или avito-review/Sonnet в Claude Code по
маршруту основного skill. Указывайте фактическую модель, а не имя из чужого примера. Отдельный экспортёр и review.json не нужны:
finalize проверяет структуру, полноту видимого шаблона и расположение, строит
CSV, паспорт и общую таблицу. Не переписывайте готовые экспорты.

Если город неизвестен реестру, подготовьте подтверждённый placements.json:

```json
{
  "1234567890": {
    "city": "Серпухов",
    "region": "Московская область",
    "evidence": "Московская обл., Серпухов"
  }
}
```

Это пример формы, не готовые данные. Используйте ID и точную цитату из своего
location_raw и добавьте --placements /path/to/placements.json к finalize.
Город — размещение на сайте, не slug URL и не место работы из описания.
Непрочитанный адрес/шаблон — повод исправить общий код по основному skill,
не выставлять успешный статус вручную. Список расширенных параметров и
обогащение не выдумывайте.

Готовый файл: Data/avito_runs/<run_id>/exports/vacancies_flat.csv.
Проверьте его через csv.DictReader или pd.read_csv, число уникальных ID и
сохранность описаний/расположения. При командном сборе продолжайте publish по
основному skill; локальная проба не публикуется автоматически.

```sh
python3 utils/build_dataset.py --check
```

Ожидается код возврата 0 и число вакансий/колонок без ошибки. Эта проверка
читает CSV из реестра, проверяет схему, уникальные ID, исходные хеши и точное
соответствие общей таблицы принятым выгрузкам. При ошибке не сообщайте о готовности.

Готовность означает: preflight разрешает сбор, реальные карточки прочитаны
и CSV открывается. Список установленных программ сам по себе этого не
доказывает. В отчёте укажите ОС и непроверенные платформы.
